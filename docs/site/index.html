为什么是 ReinsWhy Reins

Teleport 换了许可证、MeshCentral 的 Agent 总被杀软盯上、TacticalRMM 是套 Python 全家桶——你需要一个真开源、单二进制、企业级安全原语齐全的远程运维平面。

🔒

零入站端口

Agent 反向 WebSocket 出站连接穿透 NAT。你的主机对互联网完全不可达——这是 NIST 800-207 说的"消除隐式网络信任"。

🐴

单二进制

Relay 是一个静态 Go 二进制(bbolt 持久化,零外部依赖;Redis 可选水平扩展)。不是 Docker Compose 十件套。

🪪

每设备一个身份

mTLS + 内置 CA + CRL 吊销;多租户 RBAC(admin/operator/viewer)+ 组织配额隔离;命令黑/白名单 Relay 与 Agent 双侧执行。

📜

审计链防篡改

hash chain 审计日志 + CEF/Syslog SIEM 导出 + 会话录屏(asciinema)。这正是 CISA AA23-025A 要求企业盘点的 approved-RMM 该有的样子。

🤖

AI 代理的缰绳

被管项目在仓库根写 .reins/rules.md 运维规则——AI/自动化必须先 rules read 读规则并携带内容指纹 ack,规则一改旧 ack 立即失效。先读规则,再碰服务器。

⚙️

运维而非远控桌面

批量分发(重试+SSE 进度)、DAG 编排(失败级联跳过)、部署 playbook、进程守护、快照 diff、网络诊断、日志聚合——50+ CLI 命令一个终端管一个舰队。

快速开始Quickstart

Docker Compose 一键起 Relay(内嵌 Web 控制台);被控端一行命令装 Agent。

bash
$ git clone https://github.com/V-T-V/reins && cd reins
$ echo "REINS_TOKEN=change-me" > .env && docker compose up -d
reins-relay  |  ✅ HTTP 监听 :7780

# Windows 被控端(PowerShell,一行):
PS> iex (((irm 'http://your-server:7780/install.ps1') -replace '^\uFEFF'))

生产部署(Nginx TLS 终端/Helm/systemd/自更新)见 部署指南。

零信任对照NIST 800-207 mapping

NIST 800-207 概念Reins 机制
消除隐式网络信任Agent 仅出站反向 WS;主机零入站端口
每请求/每设备身份mTLS 客户端证书(内置 CA 签发,一机一证)
动态最小权限tenant:role:secret RBAC + 命令白名单交集语义
持续评估留痕hash chain 审计 + CRL 吊销即断链 + 会话录屏
