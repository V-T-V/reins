📋 平台概览

go-rmm 是一个 Go 实现的远程自动化执行操作平台，通过反向 WebSocket 中继，让 Web 控制台远程驱动 Windows Agent 执行自动化任务。

三组件架构

┌─────────────────┐    HTTPS/SSE     ┌──────────────────┐   反向WS长连接   ┌────────────────────┐
│  Web 控制台      │ ────────────────►│  Relay 中继服务器  │◄─────────────────│  Windows Agent      │
│  (浏览器)        │                  │  (公网/局域网)    │   主动外连+心跳   │  (kardianos 服务化) │
│  原生JS+embed.FS │  ◄── 结果SSE推送 │  Go net/http     │                  │                     │
└─────────────────┘                  └──────────────────┘                  └─────────────────────┘
                                                                                 ├ powershell  执行命令
                                                                                 ├ script      执行脚本
                                                                                 ├ file        文件操作
                                                                                 ├ screenshot 窗口截图
                                                                                 ├ browse      浏览器自动化
                                                                                 ├ guiclick    视觉点击
                                                                                 ├ shell       交互终端
                                                                                 └ transfer    大文件传输(5GB+)

🚀 快速开始（本地三端联调）

三个终端，30 秒跑通完整系统：

# 编译三组件
make all

# 终端 1：Relay（中继服务器）
./bin/go-rmm-relay -addr :7780 -dev

# 终端 2：Agent（前台调试）
./bin/go-rmm-agent run -relay ws://127.0.0.1:7780/agent -id my-agent

# 终端 3：Console（Web 控制台）
./bin/go-rmm-console -addr :7781 -relay http://127.0.0.1:7780

浏览器打开 http://localhost:7781，左侧看到 Agent，下发 PowerShell 任务，实时查看结果。

💡 一键脚本
.\scripts\demo-local.ps1   # PowerShell 一键编译+启动

🌐 场景一：内网部署（Tailscale + Token）

适合个人/小团队，几台机器在同一虚拟内网。零自建公网服务器。

步骤

  1. 所有机器安装 Tailscale 并登录同一账号
  2. 选一台机器跑 Relay + Console
# Relay（绑定 Tailscale IP，设置 token）
./go-rmm-relay -addr 100.x.x.relay:7780 -token "$(openssl rand -hex 16)"

# Console
./go-rmm-console -addr 100.x.x.relay:7781 -relay http://100.x.x.relay:7780
  1. 被控机器安装 Agent
# Windows（管理员 PowerShell）
.\go-rmm-agent.exe install `
    -relay ws://100.x.x.relay:7780/agent `
    -token <你的token>
.\go-rmm-agent.exe start
⚠️ 安全提示
Tailscale 自身加密，但 Relay 与 Agent 间流量在 Tailscale 隧道内仍是明文。若需端到端加密，用公网 mTLS 部署。

🔐 场景二：公网部署（mTLS + CA）

适合跨公网控制，或对安全有严格要求。全链路 mTLS 加密。

1. 服务器准备 TLS 证书

# Let's Encrypt（有域名）
certbot certonly --standalone -d relay.example.com

# 或自签（无域名）
openssl req -x509 -newkey rsa:4096 -keyout relay.key -out relay.crt -days 365 -nodes \
    -subj "/CN=relay.example.com"

2. 启动 Relay（mTLS 模式）

./go-rmm-relay \
    -addr :7780 \
    -mtls \
    -tls-cert /path/to/relay.crt \
    -tls-key /path/to/relay.key

首次启动自动生成内置 CA：data/ca-root.crt（10年）+ data/ca-root.key（0600）+ data/ca-state.json（CRL 状态）。

3. 为 Agent 签发证书

# 生成一次性注册令牌（1小时有效）
curl -X POST http://localhost:7780/api/enroll-token \
    -H "Content-Type: application/json" \
    -d '{"agent_id": "agent-prod-01"}'
# 返回: {"token":"a1b2c3...","expires_in":3600}

4. Agent 首次注册

.\go-rmm-agent.exe run `
    -relay wss://relay.example.com:7780/agent `
    -id agent-prod-01 `
    -mtls `
    -token 

# 首次连接后自动 enroll，证书落盘 data/agent.crt + data/agent.key
# 之后注册为服务
.\go-rmm-agent.exe install -relay wss://relay.example.com:7780/agent -id agent-prod-01 -mtls

5. 撤销 Agent（如有失陷）

curl -X POST http://relay:7780/api/agents/revoke \
    -d '{"agent_id": "agent-prod-01"}'
# 撤销后 mTLS 握手被拒（CRL 校验），Agent 立即断开

⚙️ Agent 服务化管理

Windows 服务

.\go-rmm-agent.exe install -relay ws://relay:7780/agent -token 
.\go-rmm-agent.exe start       # 启动
.\go-rmm-agent.exe stop        # 停止
.\go-rmm-agent.exe status      # 状态
.\go-rmm-agent.exe uninstall   # 卸载
.\go-rmm-agent.exe run         # 前台调试（不注册服务）

Linux systemd

./go-rmm-agent install -relay ws://relay:7780/agent -token 
sudo systemctl start go-rmm-agent
journalctl -u go-rmm-agent -f    # 看日志

配置文件（config.json）

{
  "agent_id": "agent-prod-01",
  "relay_url": "wss://relay.example.com:7780/agent",
  "token": "your-token",
  "mtls": true,
  "heartbeat": 15000000000,
  "max_concurrent_tasks": 4,
  "tags": { "env": "prod", "role": "web" },
  "glm": {
    "api_key": "your-glm-key",
    "model": "glm-5-turbo"
  }
}
💡 配置说明
  • tags 用于批量下发（如 env=prod 匹配所有 prod Agent）
  • max_concurrent_tasks 默认 4，防止被并发任务打爆
  • glm.api_key 配置后 guiclick（视觉点击）能力才启用
  • mtls: true 时 token 作为 enrollment token（首次注册），之后用证书
  • 权限自动 0600（含 token/glm key 等敏感信息）

📦 大文件传输（5GB+）

专用二进制 WS 帧通道，支持 5GB+ 文件快速传输，stream-through 中继不落盘。

上传文件到 Agent

curl -X POST "http://relay:7780/api/transfer/upload?agent_id=agent-01&path=C:\big.bin&transfer_id=xfer1" \
    --data-binary @local-big-file.bin

从 Agent 下载文件

curl -X POST "http://relay:7780/api/transfer/download?agent_id=agent-01&path=C:\report.pdf&transfer_id=xfer2" \
    -o downloaded.pdf

二进制帧

去掉 base64，省 33% 带宽

流式传输

256KB 缓冲，不全载入内存

增量哈希，完成时比对

断点续传

.part 文件 + resume_offset

SSE 推送百分比 + 速度

⏰ 定时任务（Cron）

robfig/cron 调度引擎，规则持久化到 bbolt，到点自动生成任务投递。

# 新建定时规则（每 5 分钟执行）
curl -X POST http://relay:7780/api/crons \
    -d '{
        "cron_expr": "*/5 * * * *",
        "task_type": "powershell",
        "agent_id": "agent-prod-01",
        "payload": {"command": "Get-Service | Where-Object {$_.Status -eq \"Running\"}"},
        "timeout": 30
    }'

# 列出所有规则
curl http://relay:7780/api/crons

# 删除规则
curl -X DELETE http://relay:7780/api/crons/cron-1234567890
💡 Cron 表达式
5 字段：分 时 日 月 周。如 0 */2 * * * = 每 2 小时，0 9 * * 1-5 = 工作日 9 点。

💻 交互式终端

通过浏览器直接操作远程 Agent 的 PowerShell，实时输入输出。

# 开启终端会话
curl -X POST http://relay:7780/api/shell/open \
    -d '{"agent_id":"agent-prod-01","cols":80,"rows":24}'
# 返回: {"session_id":"shell-xxx"}

# 发送命令
curl -X POST http://relay:7780/api/shell/input \
    -d '{"session_id":"shell-xxx","agent_id":"agent-prod-01","data_b64":""}'

# 关闭会话
curl -X POST http://relay:7780/api/shell/close \
    -d '{"session_id":"shell-xxx","agent_id":"agent-prod-01"}'
⚠️ 终端安全
交互式终端等于完全 shell 访问，无法做静态命令拦截。终端能力在 capabilities 里单独声明，审计记录每次 open/close。

🔧 故障排查

Agent 连不上 Relay

# 1. 前台模式看详细日志
./go-rmm-agent run -relay ws://relay:7780/agent -token xxx

# 常见错误：
#   "connection refused" → Relay 未启动或防火墙
#   "handshake error" → mTLS 证书问题
#   "unauthorized" → token 错误

# 2. 检查 Relay 健康
curl http://relay:7780/healthz

任务一直 pending

# Agent 离线 → 任务缓存 pending，等上线补投
# Agent 在线但 pool 满 → 检查 metrics tasks_nacked
# 长期 pending → 检查 metrics tasks_reaped（reaper 回退计数）

mTLS 证书过期

# Agent 客户端证书 24h 有效，自动续签
# 若续签失败（Relay 不可达超 24h）：
del data\agent.crt data\agent.key
.\go-rmm-agent.exe run -relay wss://relay:7780/agent -id  -mtls -token

持久化重启不丢任务

# Relay 重启后 bbolt 数据自动恢复
# 检查：重启后 GET /api/tasks 应仍有历史记录
# reaper 自动恢复 dispatched 任务为 pending 重投

🔒 部署安全清单

部署前逐项确认：

  1. ☐ Relay 不直接暴露 3389(RDP)/22(SSH)/5985(WinRM) 到公网
  2. ☐ 使用 Tailscale 组网或 mTLS 加密
  3. ☐ token 已设置（非空），且未硬编码在脚本仓库
  4. ☐ config.json 权限 0600
  5. ☐ ca-root.key 已离线备份，服务器上权限 0600
  6. ☐ 命令策略已启用（检查 metrics tasks_blocked > 0）
  7. ☐ 审计日志已接入收集
  8. ☐ healthz 已接入监控告警
  9. ☐ Agent max_concurrent_tasks 已按机器负载调整（默认 4）
  10. ☐ guiclick 的 GLM key 仅在需要的 Agent 配置
🚨 关键安全提示
  • 命令策略是 best-effort：黑名单正则可被变形绕过，不应作为唯一安全依赖
  • 交互式终端 = 完全 shell 访问：无法做静态命令拦截，需通过权限管理控制
  • ca-root.key 泄露 = 全系统失陷：离线冷备，定期轮换
